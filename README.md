# 지도 앱이 모르는 변수까지 읽는 길찾기

서울 지하철에서 환승이 있는 이동을 대상으로, 지도 앱이 알려주는 시간과 실제로 체감하는 시간 및 피로도의 차이를 데이터로 분석하는 데이터분석 과제입니다. 인천 → 서강대 장거리 통학, 대표 환승 허브, 공연장 주변 이동을 사례로 검증합니다.

## 1. 문제의식 (주제를 정한 이유)

1. 매일 왕복 3시간씩 통학함
2. 오래 앉아 가려고 버스만 타고 가다가 후회함. 너무 오래 걸리고 돌아가며, 버스가 바로 오지 않음
3. 지하철 칸 표시(1-1 등)만으로는 어디서 타야 출구·환승 통로와 가까운지 모름
4. 출구가 지하·지상으로 나뉘어 헷갈려서 길을 잃은 적이 많음
5. 인천행 서울 1호선 완행이 예상보다 늦게 도착한 적이 많음. 7분 늦게 온다던 용산급행을 탈걸 후회한 적이 많음
6. 환승 동선이 길고 복잡함
7. 날씨(더운 날, 습한 날)에 따라 걷는 게 나은 날과 그렇지 않은 날이 있음
8. 같은 시간인데도 날마다 사람 수가 다름. 콘서트·야구 같은 행사 때문일까?
9. 오전 10시면 출근이 끝났을 시간인데 왜 사람이 많은지 궁금함
10. 버스 배차가 매일 다름. 수요일은 늦게 나가도 괜찮았는데 지각 확정인 날도 있음

## 2. 프로젝트 구상

| 단계 | 내용 |
|---|---|
| 01 데이터 (변수 수집) | 운행 정보(실시간 도착, 과거 지연), 역 구조(환승 거리, 계단, 출구), 날씨(기온, 습도, 강수), 행사·일정(공연, 경기) |
| 02 분석 (예측) | 체감 시간(지연 가능성 반영), 체감 피로도(도보·오르내림·날씨 점수화), 혼잡 원인(행사·시간대·지연 구분), 개인 선호(도착 보장, 앉아 가기, 덜 걷기) |
| 03 결과 화면 | 앱 시간 vs 체감 시간, 오늘의 추천 경로와 이유, 환승 위치(통로와 가까운 칸, 출구 안내) |

### 범위
- **대상**: 서울 지하철(1~9호선·경의중앙선)에서 환승이 있는 모든 이동. 같은 방법을 어느 구간에나 적용함
- **사례**: ① 인천→서강대 장거리 통학(코레일 1호선 + 2호선) ② 대표 환승 허브 ③ 공연·경기장 주변 저녁 이동
- **넓게**: 인천→서울 통학 수요와 혼잡을 공공데이터 통계로 보여줌 (나만의 문제가 아님을 보여주기)
- **깊게**: 실제 경로에서 직접 수집하고 분석함
- 인천1호선은 잘 이용하지 않으므로 제외함

### 통학 경로와 비교할 대안
| 경로 | 하차역 | 특징 |
|---|---|---|
| 536번 버스 → 동암역 1호선 → 신도림 환승 → 2호선 | 신촌 | 주 경로. 신도림 환승이 혼잡함 |
| 1호선(용산급행) → 용산 환승 → 경의중앙선 | 서강대 | 학교와 가깝지만 경의중앙선 배차가 김 |
| 1호선 → 2호선 → 6호선 | 대흥 | 정문 쪽 접근성 |

### 행사 변수
- **과거 분석**: 지난 야구 시즌의 경기일과 역별·시간대별 승하차 인원을 비교함. 특히 고척스카이돔은 가까운 역이 1호선 구일역이라 통학 경로 위에 있음
- **현재 적용**: 겨울 콘서트(고척돔, KSPO DOME, 잠실실내체육관), 배구(장충), 농구(잠실학생), 신촌·홍대 행사

## 4. 환경 설정

### API 키
프로젝트 폴더에 `.env` 파일을 만들고 키를 넣습니다. `.env`는 `.gitignore`에 들어 있어 커밋되지 않습니다.
```
SEOUL_SUBWAY_REALTIME_KEY=실시간_지하철_키
SEOUL_OPENAPI_KEY=일반_인증키
DATA_GO_KR_KEY=공공데이터포털_일반인증키(Decoding)
```
- 실시간 키: `swopenapi.seoul.go.kr`
- 일반 키: `openapi.seoul.go.kr`
- 두 키는 서로 바꿔 쓸 수 없음

### 시범 호출 (PowerShell)
신도림, 신촌, 구일, 서강대 역의 실시간 도착 정보를 표로 출력합니다.
```
powershell -ExecutionPolicy Bypass -File .\test_realtime.ps1
```
노선 코드: `1001`=1호선, `1002`=2호선, `1006`=6호선, `1063`=경의중앙선

### Python
- Python 3.14 (Windows installer 64-bit), 설치 시 **Add python.exe to PATH** 체크
- 사용할 패키지: `requests`, `pandas`, `python-dotenv`

### 7일 실시간 수집 (2026-11-16 ~ 11-22)
`collect_config.json`에 수집 계획을 적고, `collector.py`가 1분마다 실행되면서 해당 시각에 맞는 작업만 호출합니다. 결과는 `data/<api>/<날짜>.jsonl.gz`(원본 필드 + 수집 시각)에 쌓이고, `data/`는 커밋하지 않습니다.

### 시범 사이트
`web/index.html`을 브라우저로 열면 됩니다. 데이터(`web/data.js`)는 수집기가 매시 5분에 다시 만들고, 바로 보고 싶으면 `py build_site.py`를 실행합니다.

| 화면 | 내용 |
|---|---|
| ① 구간 실제 소요 시간 | 같은 노선 위 어느 두 역이든, 열차 위치 기록에서 실제 걸린 시간의 분포 (일반/급행, 평일/주말). 2호선 순환(충정로↔시청)은 짧은 방향으로 이어서 계산 |
| ② 배차 간격 | 역·방향별 실제 열차 간격. 수집이 끊긴 구간은 제외 |
| ③ 도착 안내는 얼마나 맞나 | "N분 후" 안내의 오차, "N번째 전역" 안내 후 실제 대기, 안내 정보의 나이 |
| ④ 수집 현황 | 날짜×시간별 성공·실패 호출 |

정리 방식: 열차 위치 스냅샷을 열차번호별 궤적(역 ID, 시각)으로 묶고, 관측이 없는 역은 앞뒤 관측(10분 이내) 사이를 역 순서로 보간합니다. 1호선 경인선은 역 ID가 신도림(140)~인천(161)로 이어져 있어 이 방식이 그대로 적용됩니다.

## 5. 피로도 모델 (설계)

**목표:** 같은 출발·도착이라도 시각·요일·날씨·행사·개인 선호에 따라 '덜 힘든' 경로를 골라 주고, 이유를 데이터로 설명함. 지도 앱은 시간표 기준 시간 하나만 보여 줌.

피로도는 직접 잴 수 없으므로 **체감 시간(분)** 으로 나타냄. 교통 분야의 '일반화 비용(generalised cost)' 방식으로, 구간마다 힘든 정도에 맞는 가중치를 곱해 더함.

```
체감 시간 = Σ 차내 시간 × 혼잡 가중치(혼잡도)
          + Σ 대기 시간 × 대기 가중치
          + Σ 환승 보행 시간 × 보행 가중치(날씨) + 환승 횟수 × 환승 벌점
          + 지각 위험 (소요 시간 분포의 상위 10% − 중앙값) × 개인 '도착 보장' 가중치
```

| 항목 | 데이터 | 가중치 근거 (보고서에 출처 표기, 숫자는 원문 확인 후 확정) |
|---|---|---|
| 차내 시간 | 7일 수집: 구간 실제 소요 시간 분포 (시간대·요일·급행) | 기준 1.0 |
| 혼잡 | `crowding.csv` 역·방향·30분별 혼잡도, `ridership_hourly.csv` | 혼잡할수록 차내 시간 가중치 증가. 영국 메타분석(Wardman & Whelan, 2011)은 앉아 가기 약 1.2배, 서서 가기 약 2.3배 수준 보고 |
| 대기 | 7일 수집: 실제 배차 간격, 도착 안내 오차 | 영국 교통 평가 관행은 대기·도보 시간을 차내 시간의 2배로 봄. 최근 메타분석은 1.5~1.75배로 낮추자고 제안 |
| 환승 보행 | `transfer_distance.csv` (거리 m, 1.2 m/s 기준 시간) | 보행 가중치와 같게. 비·추위·더위면 더 무겁게 (기상청 자료) |
| 행사 | 공연·경기 일정 + 그 시간대 승하차 인원 증가 | 행사 시간대 혼잡도 보정 |
| 개인 선호 | 사용자가 고름: 앉아 가기 / 덜 걷기 / 꼭 제시간 도착 | 해당 항목 가중치를 키움 |

**검증:** 가중치는 문헌값으로 시작하고, 설문(같은 출발·도착의 두 경로 중 덜 힘든 쪽 고르기)으로 모델이 사람들의 선택을 얼마나 맞히는지 확인함.

**사례:** 통학(인천→신촌), 직장(강남·여의도), 번화가(홍대·성수), 공연장(KSPO DOME·잠실). 사례마다 후보 경로 2~4개를 두고 시각별 체감 시간을 비교함.
